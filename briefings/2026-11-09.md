## AI Coding & Developer Tools

### Claude Code's 'do not ask again' prompt is leading to passwords and API keys being exposed on GitHub.

[Explained](https://ethany1017.github.io/ai-briefing/2026-11-09.html#claude-code-s-do-not-ask-again-prompt-is-leading-to) · [Source](https://arstechnica.com/ai/2026/11/claude-code-settings-files-expose-thousands-of-secrets-on-github/) (Ars Technica AI)

**What happened:** Security researchers at Apiiro found that Claude Code can leave secrets in public GitHub repositories. When a user picks the option to approve a command and not be asked again, the command is saved in a local settings file, sometimes with passwords or keys inside it. That file is meant to stay out of sharing, but the protection does not carry over to the repo level. They found over 100,000 uploaded settings files, and about 1,100 from 63 organizations contained secrets.

**Why it matters:** It shows that convenience features in AI coding tools can create quiet security holes. The problem is not one dramatic bug but a small settings gap that adds up at scale. Secrets can also survive in forks even after the file is removed.

**What it means for you:** Check your own repos for this settings file and make sure it is ignored in the repo itself. Do not put passwords or keys directly in commands you approve. If you ever pushed a secret, treat it as exposed and replace it, because deleting the file is not enough.

## AI Research & Breakthroughs

### Flex-RSI is a new benchmark testing whether frontier agents can recursively improve their own harnesses.

[Explained](https://ethany1017.github.io/ai-briefing/2026-11-09.html#flex-rsi-is-a-new-benchmark-testing-whether-frontier-agents) · [Source](https://arxiv.org/abs/2611.08946) (arXiv cs.AI)

**What happened:** Researchers introduced Flex-RSI, a benchmark that tests whether AI agents can improve the way they work, not just their answers. An agent's harness is the prompts, tools, memory and control loop around the model. In each round, one part improves the solution and another revises the harness. They tested closed-source and open-weight models on vision and robotics tasks and found self-improvement helped most when the agent built its own solution. Open-weight models fell furthest behind on tasks needing strict correctness or physical stability.

**Why it matters:** Most tests judge an agent's final answer. This one asks whether an agent can fix its own setup, which is a step toward systems that get better with less human help. It also shows that how much feedback an agent gets matters, since simple success-or-failure signals held back open-weight models.

**What it means for you:** It is a research paper, so it will not change your daily work. The useful idea is that an agent's performance depends on its harness, not only the model. If you build agents, tuning prompts, tools and feedback is often where the gains are.

### Study finds prompt injection guards produce false positive rates up to 92% on legal contract review.

[Explained](https://ethany1017.github.io/ai-briefing/2026-11-09.html#study-finds-prompt-injection-guards-produce-false-positive) · [Source](https://arxiv.org/abs/2611.08834) (arXiv cs.AI)

**What happened:** A new paper tested eleven open prompt injection guards, which are tools that try to catch hidden malicious instructions in text, on legal contracts. It found false alarm rates as high as 92.39 percent, two guards doing worse than chance on one measure, and a simple five-pattern regex baseline that no guard clearly beat. Using a mid-tier model and double-checking its flagged items with a top model came close to the top model's performance at 6.5 times lower cost.

**Why it matters:** Many systems rely on these guards to protect AI that reads documents. If they flag almost everything harmless, they become useless or get ignored. The results suggest that general-purpose language models, checked in stages, can do better than the specialized guards tested.

**What it means for you:** If you build apps that feed documents to a model, do not trust a guard just because it is labeled for security. Test it on your own kind of data first. The cheap model first, expensive model second pattern is a practical design idea you can reuse.

### OpenAI details Control Room, a system to track and rapidly stop model workloads across its research infrastructure.

[Explained](https://ethany1017.github.io/ai-briefing/2026-11-09.html#openai-details-control-room-a-system-to-track-and-rapidly) · [Source](https://openai.com/index/control-room) (OpenAI)

**What happened:** OpenAI described Control Room, a central system that tracks model jobs across its research infrastructure and can stop them quickly. Models check with the service before producing output, so a stopped job gets refused. It halts output within 35 seconds of a decision to stop, because of a caching layer, and OpenAI says it is working to bring that to zero.

**Why it matters:** As models grow more capable, labs want a dependable way to stop them if something goes wrong. A monitor model can raise an alert, and Control Room acts on it. It is also designed to stop output if Control Room itself goes down.

**What it means for you:** This is a good real example of safe system design: a central switch that systems must ask before acting, and that fails safe. Think of a train that stops if the signal system loses power. The idea applies to ordinary software too, such as feature flags and kill switches.
